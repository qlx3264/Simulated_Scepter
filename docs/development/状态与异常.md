# 状态建模与异常处理

## 1. 每个事实只有一个权威来源

- 已有字段、集合或状态能够表达的信息，不再维护同义字段。比如已有任务集合时，通常使用 `len(tasks)`，而不额外维护随时可能失真的 `task_count`。
- 可推导的属性按需计算。确需缓存时，明确计算成本、失效条件和更新责任。
- 区分输入配置、运行状态和最终结果，不把三者混放在可任意改写的字典中。
- 需要快照、历史或跨线程消息时，明确其采集时刻和只读语义，不将其当作第二份实时状态维护。

## 2. 互斥属性用状态机表达

同一对象同一时刻只能满足其中一个属性时，必须使用单一状态及明确的转移规则，禁止分别设置多个布尔值。

```python
# 禁止：可能出现运行、暂停和结束同时为真的组合。
is_running = True
is_paused = True
is_finished = False

# 推荐：简单局部流程用一个整数变量，注释集中说明取值。
# 状态：0=待启动，1=运行，2=暂停，3=已停止，4=已完成，5=失败。
state = 0
```

**状态机是一组状态与转移规则，不要求建立专门的类。** 简单局部流程优先使用一个整数变量和清晰注释，不额外创建状态类、管理器、枚举或框架。仅声明变量也不等于完成状态机，还必须规定触发事件、允许的转移和伴随动作。例如：

| 当前状态 | 事件 | 下一状态 | 必须完成的动作 |
| --- | --- | --- | --- |
| 0（待启动） | 启动且前置检查通过 | 1（运行） | 初始化运行资源 |
| 1（运行） | 暂停 | 2（暂停） | 停止推进操作，释放已按下的输入 |
| 2（暂停） | 恢复且环境检查通过 | 1（运行） | 恢复任务推进 |
| 1（运行）/ 2（暂停） | 用户停止 | 3（已停止） | 停止任务并清理资源 |
| 1（运行） | 目标完成 | 4（已完成） | 清理资源并保存结果 |
| 活动状态 | 无法正常处理的失败 | 5（失败） | 阻止后续操作并执行失败清理 |

该表是设计示例，不要求项目照搬所有状态。整数值的含义应固定，不用 `state += 1` 隐含跳转规则，也不用未说明的大小比较猜测状态。终态是否允许重新启动应由实际需求定义，不能默认放行。

当状态确需跨模块共享、受公共接口约束，或已有适用枚举时，可以采用或复用枚举；必须说明实际需要，不能仅因使用“状态机”一词就创建类。已有合理实现不因本规则而批量改写。

- 状态转换由明确的所有者执行，禁止调用方到处直接赋值。
- 对未列出的转移明确拒绝或按约定忽略，并说明依据；不能无声跳入不合法状态。
- `sound_on` 与 `save_video` 这类独立开关可以使用布尔值。不要把互不相关的维度组合成巨大的状态枚举。
- 跨线程停止信号可以使用同步原语，但它表达的是“停止请求”，不是重复保存“已停止”的任务状态。
- 并发状态检查和更新应使用项目适用的同步方式，防止检查通过后状态已改变却继续操作。

## 3. 明确正常结果与失败

- 正常的“未识别到目标”“集合为空”等结果按契约返回，不自动升级为异常。
- 不能完成当前操作时，使用明确异常或项目约定的失败结果；不要返回空字典、`None` 或 `False` 冒充成功。
- 同一接口不能让相同返回值同时表示“正常无结果”和“执行失败”，除非调用方有明确、可靠的区分机制。
- 入口校验外部输入和环境条件；内部依据已建立的契约执行，不在每一层重复猜测类型和修补坏数据。

## 4. 捕获、恢复与传播

- 只捕获当前层能够处理或补充有效上下文的异常，禁止 `except Exception: pass`。
- 顶层任务边界可以捕获未知异常，用于记录失败和清理资源，但必须保留失败结果，不能继续报告完成。
- 降级必须有真实可行的替代路径；重试必须有适用条件、次数或时间边界，并响应停止请求。
- 禁止给所有异常统一重试。无效配置、缺失必要资源等问题不因重试自动修复。
- 记录后重新抛出的错误由一个边界负责完整日志，避免每层重复打印同一堆栈。
- 运行条件校验使用显式判断和异常；不能依赖可能被优化模式移除的 Python `assert`。

## 5. 清理必须覆盖所有出口

- 正常完成、用户停止、异常退出都必须释放自己持有的资源。
- 文件、锁、设备输入等优先使用现有的上下文管理或 `try/finally`。
- 按下的键鼠必须成对释放；停止后阻止后续输入。只有清理已确认完成，才提示“键鼠已释放”。
- 清理失败需要保留原始失败信息并说明残留影响，不允许静默覆盖原始异常或虚报停止成功。
- 不在 `finally` 中用 `return` 覆盖异常或原返回值。

错误等级及用户提示见[日志规范](日志规范.md)。日志只记录事实，不承担状态转移或异常传播职责。
