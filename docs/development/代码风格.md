# 代码风格：简洁而不简单

## 1. 命名短而准确

- Python 自有变量、参数、函数和字段采用由 **1～3 个单词组成的 `snake_case`**，例如 `frame`、`target_pos`、`retry_limit`。类名采用 `PascalCase`，常量采用 `UPPER_SNAKE_CASE`，同样优先控制在 1～3 个单词。
- 不为凑字数使用生僻缩写，也不把完整业务说明塞进名称。名称太长时，先检查作用域、对象职责是否过大，是否重复携带已有上下文。
- 同一含义使用同一名称；不同含义不得共用一个变量。单位存在歧义时写入名称，如 `wait_ms`，并注释必要的取值约束。
- `i`、`x` 等只用于含义明确的短循环或数学坐标。禁止无意义的 `data2`、`temp_result` 和把重构版本留在名称中的 `new_handler`。
- 外部接口、框架回调和生成代码遵循其约定，不为命名规则破坏兼容性。

## 2. 不滥用下划线保护

- 禁止习惯性给所有函数和属性加 `_`。仅当成员确实不属于模块或类的对外契约时，才使用单前导下划线表达内部边界。
- 不跨模块调用内部成员作为常规复用方式；需要共享时，应在原实现处明确公共接口。
- 不用 `__name` 假装提供访问安全。只有需要避免继承中的名称冲突时才考虑双前导下划线。
- 语言要求的 `__init__` 等特殊方法、明确表示丢弃值的 `_` 不受此限制。

## 3. 名称不能代替注释

名称说明“是什么”，注释说明不能从名称直接得到的业务含义、单位、约束和原因。禁止通过超长变量名代替必要注释，也禁止为每行代码添加翻译式注释。

- 注释默认使用中文；英文专有名词、库名、参数名和协议字段保留原文，不强行翻译。
- 注释重点解释业务意图、流程分段、异常原因和数据结构，包括字段含义、单位和约束。
- 复杂流程可以多写注释，帮助读者理解阶段、前置条件和关键决策；简单赋值、显而易见的循环和普通条件判断不要强行补注释。
- 禁止为注释而注释。`a = b` 后写“将 b 赋值给 a”只是复述语法，应删除。循环旁写“遍历列表”、返回语句旁写“返回结果”同样没有提供信息。删除注释后若不损失业务含义、约束或原因，就不应保留这类注释。
- 修改行为时同步更新相关注释，删除失效说明。

```python
import time

# 不推荐：固定值只用一次，却用变量名代替业务说明。
minimum_wait_seconds_before_next_click = 2
time.sleep(minimum_wait_seconds_before_next_click)

# 推荐：固定值直接写在唯一使用处，用注释解释等待原因。
time.sleep(2)  # 等待界面切换动画结束后再点击，单位为秒。
```

示例数值仅用于说明写法，不能直接当作项目运行参数。

### Docstring 使用 Google 风格

- 首行用中文简述职责；需要时补充业务约束和副作用。
- 使用 `Args:`、`Returns:`、`Yields:`、`Raises:`、`Attributes:` 等 Google 风格分段标题，说明正文默认中文，参数名与代码保持一致。
- 按实际需要保留分段，不为无参数、无返回值的函数填充空章节；不要重复类型注解已经明确表达的信息。
- 数据结构不能只写“一个字典”或“一个列表”，应说明必要的字段、元素含义、顺序或单位。
- 修改相关函数时可以同步规范其 docstring，禁止为了格式统一批量改动无关文件。

```python
def get_target(points: list[tuple[int, int]]) -> tuple[int, int]:
    """取出按业务优先级排列的首个点击目标。

    Args:
        points: 按优先级降序排列的屏幕坐标，每项为 (x, y)，单位为像素。

    Returns:
        优先级最高的目标坐标。

    Raises:
        ValueError: 没有可用目标，调用方应停止本次点击。
    """
    if not points:
        raise ValueError("没有可用的点击目标")
    return points[0]
```

此片段只展示文档格式，不要求为简单索引操作额外建立包装函数。

## 4. 不制造虚假变量与配置

- 固定值在相关实现中全文仅使用一次时，必须直接写在使用处；业务含义、等待原因或单位通过该处注释说明，不为解释业务逻辑另设变量或命名常量。`time.sleep(2)` 配合原因注释优于 `time.sleep(wait_time)`，也优于仅用一次的 `WAIT_TIME`。
- 禁止将这种单次使用的硬编码值包装成变量、字段、函数参数或配置项，制造“可以变化”的假象。名称再准确也不能使虚假变量变得必要。
- 简单、局部且含义显然的字面量可以直接使用，不强制把 `0`、空容器等全部提成常量。
- 命名常量必须具有明确且适用于所有调用处的业务语义，不能只描述数值类型或笼统用途。禁止为了消除字面量引入 `MINIMUM_WAIT_TIME` 等泛化常量，再把不同原因的等待统一套进去。
- 少量局部使用的固定值默认匿名，直接写成 `time.sleep(2)`，并在使用处注释等待的具体原因。只有其他位置确有相同语义、需要一起维护的规则时，才提取共享常量；“都是等待”或“数值都是 2”不构成相同语义。
- 提取前必须确认实际调用处、共同业务约束及是否应同步变化，再用准确名称表达该规则。禁止在不同文件分别定义一份。已有共享规则应集中维护，不能以“调用次数少”为由拆回重复实现。
- 已有常量已经表达该业务规则时必须复用，不能因为新调用处只使用一次就再次硬编码。外部协议或公共接口明确要求暴露的常量保留其契约；这些情况与为局部字面量强行起名不同。
- 参数必须具有真实输入来源或合理的调用契约。若内部函数所有调用都传同一个固定值，应优先去掉参数；外部接口则先确认兼容性。
- 禁止 `options = {"mode": "fixed"}` 再层层传递，最终只有一个分支生效。真正可配置的值应有读取入口、校验和实际使用者。

## 5. 不重复表达已有语义

- 已有变量能准确表达当前含义时直接使用。禁止无理由添加同义别名、镜像字段和可从已有状态直接推导的布尔值。
- 禁止为缩短一次访问而创建 `config_copy = config` 一类伪副本；赋值并不意味着复制。
- 只有明确要求，或明确说明用途的快照、单位转换、昂贵计算复用等情况，才引入额外表示。解释应落在必要注释或改动说明中。
- 中间变量应承载有用的计算阶段，而非仅转手同一个值。不要为了消除变量而重复执行有副作用、昂贵或时间敏感的调用。

```python
# 不推荐：同一状态维护两份语义。
running = state == 1  # 1 表示运行中。
if running:
    step()

# 推荐：简单判断直接使用已有状态。
if state == 1:  # 运行中才推进任务。
    step()
```

如果需要保留变化前的数据，`start_pos = player.pos.copy()` 是有意义的快照；应说明它用于比较移动前后的位置，而不是添加无说明的 `pos2`。

## 6. 控制流与内联

- 使用早返回、`continue` 和明确分支减少嵌套。发现连续三层以上条件嵌套时，应检查能否展开；不得为了满足层数机械拆函数。
- 禁止嵌套三元表达式、承载副作用的推导式，以及把多个操作挤在一行的写法。
- 仅转发参数、没有语义边界的包装优先移除，让调用方直接使用已有实现；调用次数多也不能证明包装有价值。简单表达式只使用一次时，通常直接写在使用处。
- 避免函数内部再定义函数并逐层嵌套。只有确需捕获局部状态的闭包、回调等情况才保留嵌套函数，并限制作用域；不能仅为流程分段而新增一层 `def`，应优先用注释分段。
- 同时检查调用深度：`a()` 调 `b()`、`b()` 调 `c()` 若只是转手参数、结果或改名，必须压平无用层级。不要用更深的调用链换取表面上更短的函数。
- 有实际业务步骤、资源生命周期、复杂算法或独立验证价值的函数可以保留，即使只调用一次。
- 不为内联而复制共享规则，不为缩短函数而制造需要往返跳转的碎片函数。
- 连续逻辑优先连续表达。同一任务中顺序执行、没有独立复用或边界价值的步骤放在一起，必要时用少量业务注释分段，不因函数行数较多就机械拆开。

```python
# 不推荐：逐层嵌套只为判断是否能够执行。
if frame is not None:
    if target is not None:
        if state == 1:  # 运行中。
            click(target)

# 推荐：前置条件失败时尽早退出当前函数。
if frame is None or target is None:
    return
if state != 1:  # 非运行状态不执行点击。
    return
click(target)
```

内联、提取函数和增设变量都应减少理解成本；不得只以行数作为判断标准。

## 7. 不添加无依据的保险代码

- 对内部契约已保证存在的字段，直接访问，不习惯性使用 `getattr`、`.get()` 或层层默认值猜测数据形态。
- 外部输入确实不确定时，在实际入口检查；已完成检查的内部流程不要重复兜底。可选字段按其真实约定处理，不能把必要字段伪装成可选字段。
- 不添加没有证据的兼容分支、备用值或异常吞噬。默认值必须具有明确业务含义，不能仅为让程序继续运行。
