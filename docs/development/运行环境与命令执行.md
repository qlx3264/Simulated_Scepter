# 运行环境与 AI 命令执行规范

## 1. 先确认环境，再运行命令

- 从项目根目录执行项目命令；确认当前目录、操作系统、Shell、工作区改动及相关项目配置。
- 阅读 `pyproject.toml` 中的 Python 版本约束、依赖、开发依赖组和工具配置，检查已有 `uv.lock` 与 `.venv`。
- Python 解释器、脚本、模块和临时验证代码一律通过 **uv 调用**，不得直接运行系统 `python`、`python3`、`py` 或 `.venv` 内的 Python 来绕开 uv。
- 不假定终端已激活虚拟环境，不根据个人机器的经验猜测解释器或包的位置。

## 2. 找不到命令不等于未安装

看到 `python`、`pip` 或 `uv` 无法识别时，先检查命令解析、PATH、可执行文件位置及访问权限，不直接断言未安装，更不能立即重装。

PowerShell 排查示例：

```powershell
Get-Command uv, python, pip -All -ErrorAction SilentlyContinue
$env:PATH -split ';'
```

若 PATH 中没有 uv，检查已知安装目录、项目说明或当前环境提供的路径；优先做有范围的定位，不盲目扫描全盘。找到可执行文件后，用绝对路径执行并验证版本：

```powershell
# 此路径是当前机器已确认的位置，其他机器应使用实际定位到的路径。
& 'E:\uv\.local\bin\uv.exe' --version
& 'E:\uv\.local\bin\uv.exe' run --no-sync python -c "import sys; print(sys.executable)"
```

`python` 或 `pip` 不在 PATH 中，不妨碍 uv 使用项目解释器；无需为了满足裸命令调用而安装它们。区分“未定位到”“权限不足”“环境未准备好”和“确实未安装”，报告实际证据。

## 3. 依赖只有一个声明来源

- 当前依赖以根目录 **`pyproject.toml`** 为准，禁止新增 `requirements.txt`、`requirements-dev.txt` 等文件作为第二套依赖来源。
- `uv.lock` 若存在，用于锁定解析结果，与 `pyproject.toml` 配套维护；不要手工编辑锁文件绕过依赖声明。
- 新增运行依赖或开发工具时，在 `pyproject.toml` 对应位置声明；使用 uv 管理必要变更，并检查依赖与锁文件差异。
- 禁止用全局安装、临时 `pip install` 或未记录的附加依赖掩盖项目缺失声明的问题。
- 不在普通测试或文档验证中顺手升级依赖、重建环境、删除锁文件或切换镜像。网络或权限失败不构成修改依赖约束的理由。

## 4. 根据目的选择 uv 命令

已准备好的项目环境中，日常检查优先使用 `--no-sync`，避免检查顺带同步依赖。它不会补齐缺失依赖，不能把因此失败的检查说成已通过。

```powershell
uv run --no-sync python -c "import sys; print(sys.executable); print(sys.version)"
```

运行已有测试脚本时采用 `uv run --no-sync python <脚本路径>`；运行模块采用 `uv run --no-sync python -m <模块名>`。尖括号内容必须替换为实际目标。运行前先确认其依赖和副作用，不假定 `pytest` 等工具已经声明或安装。

初次配置或本次任务确需同步依赖时，先确认操作范围，然后执行：

```powershell
uv sync
```

已有锁文件且要求保持锁定结果时使用 `uv sync --locked`；锁文件与声明不一致应明确处理，不能为了通过而删除锁文件。普通 `uv run` 可能检查并同步环境，使用前要清楚该副作用。

## 5. AI 实际执行的边界

- 只读检查、与任务有关的可逆编辑和必要验证，在已有授权内持续完成，不反复确认常规步骤。
- 执行脚本前阅读入口及导入副作用，确认是否会打开 GUI、接管键鼠、写文件、访问网络或启动后台任务。
- 本项目部分脚本会影响真实桌面。纯文档验证不得启动游戏自动化；实机操作需处于用户授权范围，且已明确停止方式和资源释放路径。
- 长时间任务保留进程或会话标识，读取完成状态；超时、启动成功或暂时无输出不等于任务通过。
- 临时文件限定在任务允许的位置，不覆盖已有文件；清理只处理明确由本次任务创建的内容。
- 不擅自修改全局 PATH、Git 信任配置、系统解释器或权限设置来绕过局部问题。确需调整时说明具体必要性和影响。
- 发生沙箱、网络或权限阻碍时，先尝试正确路径、已有环境等合理替代方案；仍不能完成时准确报告阻碍，不把环境失败归咎于业务代码。

## 6. 记录可复核的结果

交付时记录实际执行的命令、验证范围和结果。使用 `--no-sync`、离线环境或已有虚拟环境导致的限制应按实际影响说明。不得执行失败后改称“未安装”，也不得未经验证声称环境已修复。
